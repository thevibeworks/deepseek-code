# goose ACP / recipes / multi-model / context / architecture — raw notes (2026-08-03)

Source: reference/goose @ 370256a (Apache 2.0). Paths relative to
reference/goose/. Raw material for devlog synthesis. Companion notes:
goose-scheduler.md, goose-extensions.md.

CAVEAT (fact): this clone is NOT upstream block/goose — it is an evolved
fork ("aaif" lineage; TUI is the @aaif/goose npm package). The goosed
REST daemon crate does not exist, lead/worker provider is DELETED, and
ACP is the primary client interface. More advanced than public goose
docs describe; upstream-only features must be taken from block/goose
proper.

## 1. ACP

- Uses Zed's published Rust crates: agent-client-protocol 1.0.1,
  agent-client-protocol-schema 1.1 (unstable), agent-client-protocol-http
  1.0 (Cargo.toml:24-26).
- TWO transports, ONE handler: stdio JSON-RPC (`goose acp` →
  acp/server.rs:2310-2331) and HTTP/WebSocket (`goose serve` mounts
  AcpHttpServer on axum at /acp; token auth GOOSE_SERVER__SECRET_KEY;
  transport/mod.rs:101-208). GooseAgentConnection defers agent creation
  per connection (server.rs:2278-2308).
- One struct GooseAcpAgent holds sessions map, active runs, OnceCell
  client capabilities, permission manager, provider inventory
  (server.rs:197-220). Typed match-chain dispatch; everything nonstandard
  under `_goose/unstable/*` custom methods (~80 of them) generated by a
  proc macro that also exports JSON schema → generated TS SDK
  (goose-acp-macros, ui/sdk).
- Session model: ACP session id == SQLite sessions.db row id.
  session/load REPLAYS full history as normal session/update
  notifications (load_session.rs:59-210). Also fork/list/close/set_mode/
  set_config_option (provider|mode|model|thinking_effort).
- Prompt loop mapping (server.rs:1744-1957): internal AgentEvent stream →
  ACP notifications: Text→Agent/UserMessageChunk, Thinking→
  AgentThoughtChunk, ToolRequest→ToolCall (+async LLM label enrichment),
  ToolResponse→ToolCallUpdate, ActionRequired→request_permission or form
  elicitation, McpNotification→tool progress; end = UsageUpdate +
  PromptResponse{stop_reason}.
- ONE ACTIVE RUN per session; second session/prompt rejected with "use
  steer" (server.rs:1548-1577); mid-run input via
  _goose/unstable/session/steer queue drained at next loop iteration
  (agent.rs:2097-2122).
- Permissions: agent pauses on ToolConfirmation → agent→client
  session/request_permission with AllowAlways/AllowOnce/RejectOnce/
  RejectAlways; transport error ⇒ auto-cancel (server.rs:1210-1273).
  Whether to ask decided by PermissionInspector per GooseMode
  (auto/approve/smart_approve/chat).
- Client fs/terminal delegation: if client advertises fs.read/write or
  terminal caps, the developer extension's client is SWAPPED for
  AcpTools routing edits through client fs/read_text_file etc. — free
  native editor integration (acp/fs.rs:29-77, server.rs:771-831).
- Minimal interoperable ACP server: initialize, session/new,
  session/prompt → stop_reason, session/cancel, and outbound
  session/update (agent_message_chunk, tool_call, tool_call_update).
  Everything else is additive.

## 2. Recipes

- Recipe struct (recipe/mod.rs:41-86): version/title/description
  required; instructions, prompt, extensions, settings{provider, model,
  temperature, max_turns}, parameters, response{json_schema},
  sub_recipes, retry.
- minijinja templating over the WHOLE file pre-deserialization;
  recipe_dir builtin param; param precedence --params > default >
  interactive user_prompt > error; input_type:file substitutes contents;
  declared params must exactly match template vars both ways
  (template_recipe.rs, validate_recipe.rs).
- Search paths: cwd → $GOOSE_RECIPE_PATH → ~/.config/goose/recipes →
  .goose/recipes → .agents/recipes → ~/.agents/recipes.
- instructions → system-prompt extension; prompt → first user message;
  recipe extensions REPLACE user's enabled set; response.json_schema
  becomes a final-output tool.
- Sub-recipes via generic `summon` platform extension (delegate/load
  tools), parent values override params, subagents cannot delegate
  (depth 1), async delegation returns task id.
- Retry/success-check: RetryConfig{max_retries, checks:[shell cmds all
  must exit 0], on_failure cmd, timeouts}; fires when a turn ends with
  no tool calls; on failure: run on_failure, RESET conversation to
  initial messages, retry (agents/retry.rs:100-162). Deterministic
  verifier loop — same shape as our eval verify.sh.
- Security gap: only hidden-unicode scanning, enforced on ACP save but
  not `goose run`; deeplinks unsigned; recipe extension commands unvetted.

## 3. Multi-model (lead/worker DELETED in this fork)

- Fast-model tier: GOOSE_FAST_MODEL → provider fast model → main;
  complete_fast() runs thinking-off and falls back to main on ANY error
  (model_config.rs:81-153). Used for: session naming, compaction,
  tool-pair summaries, label enrichment. == our flash-for-plumbing idea.
- Planner/executor /plan (CLI): separate GOOSE_PLANNER_* provider;
  classifier decides plan-vs-questions via substring contains("plan") —
  fragile (session/mod.rs:251-279); accepting a plan clears history,
  forces Auto mode, replays plan as user message.
- Per-session provider/model switching via ACP set_config_option is the
  real multi-model mechanism; SQLite provider inventory w/ model
  catalogs, 24h staleness.
- AcpProvider: other ACP agents (claude, codex, copilot, amp, pi) usable
  as BACKENDS — agent-as-provider composition (acp/provider.rs).
- Toolshim: GOOSE_TOOLSHIM=1 strips tools and uses a separate local
  model to extract tool calls from free text.

## 4. Context management

- Pre-turn trigger: usage.total_tokens / context_limit >
  GOOSE_AUTO_COMPACT_THRESHOLD (0.8 default) checked once per reply();
  provider-reported usage preferred, tiktoken only fallback
  (context_mgmt/mod.rs:215-267).
- Compaction: prompts/compaction.md → STRUCTURED JSON summary
  (files/errors/pending/next), produced by the fast model; if the
  compaction call itself overflows, progressively drop 0/10/20/50/100%
  of tool responses middle-out. Old messages NOT deleted — flipped
  agent-invisible; summary stored agent-only; last user message
  re-appended verbatim (mod.rs:78-188).
- Mid-run overflow: ContextLengthExceeded inside the stream → automatic
  recovery compaction + reissue, max 1 recovery per stall, counter reset
  on any successful chunk (agent.rs:2718-2777).
- Incremental valves: tool-pair summarization in batches of 10 past a
  cutoff; >200k-char tool results spill to files
  (large_response_handler.rs); "~Nk tokens remaining" hint injected
  after 50% budget (moim.rs).
- Token counting: tiktoken o200k_base + blake3-keyed LRU, fallback only.

## 5. Architecture

- Crates: goose (core), goose-cli, goose-mcp (builtin servers),
  goose-providers/-provider-types, goose-sdk/-sdk-types (uniffi
  Python/Kotlin bindings), goose-acp-macros, download-manager,
  local-inference. NO goose-server/goosed.
- Agent loop: agents/agent.rs reply→reply_internal→async_stream turn
  loop: drain steers → final-output check → stop-hook gate → turn count
  (GOOSE_MAX_TURNS default 1000) → MOIM injection → provider stream →
  tool dispatch/permission → repeat. AgentManager LRU ≤100 agents keyed
  by session id.
- Desktop = Electron spawning `goose serve`, connecting as an ACP CLIENT
  over WebSocket /acp?token=... — no REST API at all.
- Hooks: PreToolUse/PostToolUse(+Failure)/SessionStart/SessionEnd/
  UserPromptSubmit/BeforeReadFile/AfterFileEdit/Before+AfterShell/Stop;
  Stop hooks can DENY completion and loop the agent with a block cap.

## Patterns worth borrowing (agent's assessment, concurred)

1. ACP as the one client protocol, stdio + WebSocket sharing a single
   handler — kills the REST/SSE daemon split.
2. Namespaced typed custom methods (+generated SDK) as the extension
   path without forking the base protocol.
3. Permission-as-outbound-request + mode inspector deciding when to ask.
4. Compaction via visibility flags (not deletion), provider-usage-driven
   trigger, single-retry overflow recovery.
5. Client-fs/terminal delegation keyed off ACP capabilities.
6. One active run per session + steer queue for mid-run input.
